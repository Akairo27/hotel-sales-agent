# دليل نشر لوحة الإدارة — خادم العرض

هذا الملف يوثّق تشغيل خادم العرض (`149.104.71.71`) كقواعد دائمة، لا
كملاحظات جلسة. الدليل الكامل (تثبيت nginx وNode وsystemd والشهادة) يُكتب
هنا بعد نجاح النشر فعليًا — انظر خطة النشر المعتمدة للتفاصيل الكاملة قبل
ذلك.

---

## ملاحظات تتكرر بين الجلسات

مسألتان ظهرتا أثناء إعداد الوصول لهذا الخادم، وستتكرران في أي جلسة قادمة
تتعامل معه ما لم تُسجَّل هنا:

### ١. مسار SSH الصحيح على ويندوز

استخدم عميل ويندوز الأصلي **`C:\Windows\System32\OpenSSH\ssh.exe`**
(أو المسار المكافئ داخل Git Bash: `/c/Windows/System32/OpenSSH/ssh.exe`)
— **وليس** `ssh` كما يأتي افتراضيًا على `PATH` داخل Git Bash
(`/usr/bin/ssh`، من حزمة OpenSSH التي توزّعها Git for Windows نفسها).

**السبب:** المفتاح الخاص (`C:\Users\joano\.ssh\id_rsa`) محميّ بكلمة مرور،
ومُحمَّل في خدمة ويندوز `ssh-agent` (عبر أنبوب مسمّى نظامي، وليس متغير بيئة
`SSH_AUTH_SOCK`). عميل Git Bash لا يعرف كيف يتحدّث مع أنبوب هذه الخدمة —
فيفشل بخطأ `Permission denied (publickey,password)` يوهم بأن المفتاح
خاطئ أو أن كلمة المرور ناقصة، بينما السبب الحقيقي هو العميل الخطأ. عميل
ويندوز الأصلي فقط يتحدّث مع هذه الخدمة تلقائيًا.

إن ظهر هذا الخطأ رغم أن `ssh-add -l` (من PowerShell) يُظهر المفتاح
محمَّلاً، فالمشكلة العميل المستخدَم، لا المفتاح.

### ٢. مساحة التبديل (swap) موجودة من قبل — لا تُنشئ شيئًا

الخادم فيه **٤ غيغابايت تبديل مُهيَّأة مسبقًا من مزوّد الاستضافة**
(ملف `/swap.img`)، لم تُنشئها خطة النشر ولا أي جلسة عمل على هذا المستودع.
ظهرت عند فحص الخادم الأول (`free -h` / `swapon --show`).

**لا تُنشئ ملف تبديل جديد ولا تفترض عدم وجوده.** أي خطوة تتحقق من التبديل
(قبل بناء `next build` مثلًا، لتفادي قتل العملية صامتًا على ذاكرة محدودة)
يكفيها التأكد من وجود التبديل الحالي — لا إضافة `/swapfile` فوقه.
